# Рисование через плагин Claude for Figma by Dubrovskiy

Через мост (`bridge/`) команды доступны как инструменты `figma_status`, `figma_command`, `figma_batch`, `figma_screenshot`.
Плагин принимает JSON-команды `{ "command": "...", "params": { ... } }` и выполняет их в открытом файле Figma.
Справочник параметров — `figma-plugin/README.md`, живой список — команда `list_commands`.

## 1. Порядок работы

1. **Сначала прочитать, потом рисовать.** `get_document_info` → `get_page { depth: 1 }` или `get_selection`. При правке существующего макета сохранять его палитру, шрифты и сетку.
2. **Проверить шрифты.** Названия начертаний зависят от файла (`"Semi Bold"` ≠ `"SemiBold"`). Перед первым использованием семейства — `list_fonts { family: "..." }`. Не угадывать.
3. **Строить одним `batch`.** Слайд или блок целиком — одна команда `batch`; ссылки `"$N"` дают id созданных узлов (`parentId: "$0"`). Делить на несколько пакетов только при переходе между страницами или после ошибки.
4. **Сохранять id.** Каждый результат возвращает `id`; следующий запрос ссылается на них строками. Состояние между запросами не хранится.
5. **Проверить глазами.** После сборки — снимок (`figma_screenshot { id }` в Claude Desktop или `export_node { id, scale: 0.5 }`) и оценить PNG. Исправить и проверить один раз повторно; не повторять экспорт без изменений.
6. **При ошибке `batch`** вернёт `error.index`: команды до него уже выполнены. Не перезапускать весь пакет — продолжить с упавшей команды или удалить созданное (`delete_node { ids }`).

## 2. Правила API, на которых ломаются макеты

| Правило | Как соблюдать в командах |
|---|---|
| Новые слои на странице без координат встают в (0,0) поверх остального | Плагин сам ставит их правее самого правого слоя. Явные `x`/`y` отключают это |
| Цвета | Только hex: `"#RRGGBB"` или `"#RRGGBBAA"` (альфа → `opacity` заливки). Градиент — `{ "type": "linear", "stops": [...], "angle": 90 }` |
| `resize` сбрасывает размеры auto layout в FIXED | Плагин применяет `width`/`height` раньше режимов. Для «по содержимому» передавать `primaryAxisSizingMode: "AUTO"` / `counterAxisSizingMode: "AUTO"` вместе с размерами |
| Два разных набора значений | У ребёнка `layoutSizingHorizontal/Vertical`: `FIXED` \| `HUG` \| `FILL`. У самого фрейма `primaryAxisSizingMode/counterAxisSizingMode`: `FIXED` \| `AUTO`. Не путать |
| `HUG` | Только у auto layout фрейма и у текста внутри него. Прямоугольнику — `FILL` или `FIXED` |
| `FILL` | Только у ребёнка auto layout фрейма, не `ABSOLUTE`. Родитель-HUG не даёт FILL-детям места — родитель должен быть FIXED/FILL |
| Текст без `width` растёт в одну строку | Для абзацев всегда передавать `width` (или `layoutSizingHorizontal: "FILL"`) — плагин переключит перенос строк |
| `lineHeight`, `letterSpacing` | `24` (px), `"120%"`, `"auto"` |
| `counterAxisAlignItems` | `MIN` \| `CENTER` \| `MAX` \| `BASELINE`. `STRETCH` не существует — растягивать детей через `FILL` |
| Иконки | Только `create_svg` с `viewBox` и `width`/`height`. Не собирать из повёрнутых линий: поворот идёт вокруг угла, а не центра |
| `create_vector` | Путь только из абсолютных `M L Q C Z`, числа через пробел. Иначе — `create_svg` |
| Перенос в другого родителя | Координаты не сбрасываются — передавать `x`/`y` в `move_to_parent` |
| Связанные элементы (стопка, ряд, карточки) | Контейнер с `layoutMode`, а не абсолютные координаты: так текст не наезжает при изменении |

## 3. Слайды 1920×1080

**Содержание**
- Один слайд — одна мысль, считываемая за 3–5 секунд. Не помещается — два слайда, а не мельче шрифт.
- Сначала решить, что слайд *делает* (вводит, доказывает, пауза, вывод), потом раскладку.

**Типографика**
- Иерархия с большим шагом: заголовок 80–140, подзаголовок 36–48, текст 24–32, подписи 18–22.
- Абзацы и списки — по левому краю. По центру — только заголовки, цитаты, одна строка.
- Пара шрифтов: акцидентный для заголовков + рабочий для текста. Насыщенность (Light/Bold) — инструмент.

**Цвет**
- Один ведущий цвет, один вторичный, один акцент. Палитра от темы презентации.
- Текст на тёмном фоне — почти белый. Акцентный цвет — на заголовки, метки, фигуры, не на абзацы.
- Фон — часть композиции: градиент, цветовые поля, крупные фигуры у краёв.

**Композиция**
- Асимметрия (70/30) сильнее 50/50. Смещать якорь контента от слайда к слайду.
- Использовать края: фигуры, выходящие за кадр (`clipsContent: true` у слайда), заголовки в углах.
- Минимум один нетекстовый элемент на слайд. Один повторяющийся мотив на всю презентацию, заметный (не 5% прозрачности).
- Ритм колоды: плотные слайды чередовать с «паузами» с одной мыслью.

**Избегать**
- Одинаковой структуры на всех слайдах («заголовок сверху + список»).
- Линии под каждым заголовком.
- Плоской иерархии (весь текст 18–24).
- Всего в карточках со скруглением: цифра может быть просто крупной цифрой.
- Блеклого текста ради «настроения».

## 4. Шаблон: слайд за один запрос

```json
{ "command": "batch", "params": { "commands": [
  { "command": "create_frame", "params": { "name": "01 — Title", "width": 1920, "height": 1080, "clipsContent": true,
      "fill": { "type": "linear", "stops": ["#0B1220", "#16233D"], "angle": 90 } } },
  { "command": "create_ellipse", "params": { "parentId": "$0", "x": 1260, "y": -240, "width": 900, "height": 900, "fill": "#3B82F6" } },
  { "command": "create_text", "params": { "parentId": "$0", "x": 120, "y": 360, "width": 1100,
      "text": "Одна мысль на слайд", "fontFamily": "Inter", "fontStyle": "Bold", "fontSize": 120, "lineHeight": "105%", "fill": "#F8FAFC" } },
  { "command": "create_text", "params": { "parentId": "$0", "x": 120, "y": 640, "width": 900,
      "text": "Подзаголовок, поясняющий тезис", "fontSize": 40, "fill": "#E2E8F0" } },
  { "command": "select", "params": { "ids": ["$0"] } }
] } }
```

Несколько слайдов — по одному `batch` на слайд, фреймы в ряд (плагин сам ставит каждый новый правее предыдущего).

## 5. Изменение кода плагина

- Типы API — `figma-plugin/node_modules/@figma/plugin-typings/plugin-api.d.ts`; любое свойство проверять по ним. Запись несуществующего свойства в узел бросает `object is not extensible`.
- Обращаться к свойствам только после проверки типа (`node.type === "TEXT"`, `"children" in node`).
- Любую правку текста — после `loadFontAsync` всех шрифтов узла.
- Манифест использует `documentAccess: "dynamic-page"`: только асинхронные API (`getNodeByIdAsync`, `setCurrentPageAsync`, `loadAllPagesAsync`).
- После изменений: `npm run typecheck && npm run build`.
