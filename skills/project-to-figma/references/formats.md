## Презентации

**Размер:** 1920×1080, `clipsContent: true` (фигуры могут выходить за край — так и задумано).

**Шкала текста:** заголовок 80–140 · подзаголовок 36–48 · текст 24–32 · подписи 18–22. Шаг между уровнями крупный — заголовок должен доминировать.

**Поля:** 96–160 px от краёв; сетка 12 колонок по 1920 — колонка ≈ 120, межколонник 40.

**Принципы**
- Слайд — одна мысль, считываемая за 3–5 секунд. Больше материала → больше слайдов.
- Раскладка следует из роли слайда: титул, тезис, доказательство (цифра/график), сравнение, процесс, цитата, пауза, призыв.
- Асимметрия (70/30) живее 50/50. Меняй точку привязки контента от слайда к слайду.
- Минимум один нетекстовый элемент на слайд; один повторяющийся мотив на всю колоду — заметный, не на 5% прозрачности.
- Абзацы и списки — по левому краю; по центру — только короткие заголовки и цитаты.
- Ритм колоды: тёмные титул и финал, светлее середина — или единая тема, но осознанно; плотные слайды перемежай «паузами».

**Чего избегать:** одинаковая структура на всех слайдах; линия под каждым заголовком; весь текст 18–24; всё в карточках; блеклый текст на тёмном ради «настроения».

**План колоды** (пример на 8 слайдов): титул → проблема (одна цифра крупно) → решение (тезис + визуал) → как работает (процесс 3–4 шага) → результаты (2–3 метрики) → сравнение → команда/доверие → призыв.

## Экраны

| Устройство | Фрейм | Поля | Сетка |
|---|---|---|---|
| Мобильный | 390×844 | 16–24 | 4 колонки, межколонник 16 |
| Планшет | 834×1194 | 32 | 8 колонок |
| Десктоп | 1440×900 (лендинг — высота по контенту) | 80–120 | 12 колонок, контейнер 1200–1280 |

**Шкала текста (UI):** H1 32–40 (мобильный) / 48–64 (десктоп) · H2 24–32 · тело 16–18 · подписи 13–14. Межстрочный 120–130% у заголовков, 140–150% у текста.

**Принципы**
- Структура: статус-бар/навбар → контент → навигация (таббар) для мобильного; хедер → hero → секции → футер для лендинга.
- Всё повторяющееся — в auto layout: списки, карточки, кнопки, поля, таббар.
- Касаемые элементы ≥ 44×44 (мобильный). Кнопка: высота 48–56, радиус по тону.
- Состояния важных экранов при необходимости — отдельными фреймами рядом: `Home`, `Home / Empty`, `Home / Loading`.
- Реальный контент из проекта: названия разделов, тексты кнопок, цены, имена.

## Прототипы

Плагин не создаёт интерактивные переходы (prototype links). Прототип рисуется как **схема флоу**:

1. Экраны в порядке сценария — в один ряд (плагин ставит их по очереди слева направо), имена `01 Onboarding`, `02 Sign up`, …
2. Отдельный фрейм-подложка `Flow` под экранами или стрелки `create_line` между ними + подписи действий («Тап “Продолжить”»).
3. В отчёте — список переходов: `01 → 02 по кнопке «Начать»` — по нему переходы легко связать вручную в режиме Prototype.

Сначала согласуй в брифе список экранов и переходов — это и есть сценарий.

## Схемы

Фреймворки, матрицы, процессы, воронки, оргструктуры, roadmap. Фрейм 1920×1080 (для вставки в презентацию) или по содержимому.

| Тип | Построение |
|---|---|
| Матрица 2×2 | Две оси `create_line` + подписи осей, 4 квадранта-прямоугольника `surface`, в каждом заголовок и 1–2 строки |
| Процесс / шаги | Горизонтальный auto layout из карточек-шагов с номерами; стрелки между ними или общая линия |
| Воронка | Стопка трапеций — `create_vector` или `create_svg` с уменьшающейся шириной, цифра и подпись на каждом уровне |
| Оргструктура / дерево | Уровни сверху вниз, карточки узлов, связи линиями; ровный шаг по уровням |
| Roadmap / таймлайн | Горизонтальная ось, вехи-кружки, подписи дат и событий над/под осью поочерёдно |
| Сравнение | Колонки-варианты, строки-критерии; выигрышный вариант выделен `primary` |

Принцип: цвет кодирует смысл (категория, статус), а не украшает. Подпись каждого элемента ≤ 6 слов; пояснение — мелко под ним.
